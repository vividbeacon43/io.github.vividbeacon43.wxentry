# WXEntry 2.09 / 动态内核 v250

对应免费、高级、VIP三通道v250和模块APK2.09。修复前台红包自动拉起固定使用旧领取页的问题，改为委托微信原生钱包领取入口，跟随微信选择新版或旧版页面，并保留完整原生红包模型。

## 定位依据

用户13:43上传的免费版报告实际运行内核v248。日志显示自动启动旧领取页，且查询返回可领取，但没有自动点击记录。v248修复的空应用上下文问题已经解除；这不能证明该设备已经完成领取。

检查当前原微信APK发现，聊天中点击红包和钱包领取入口均调用同一原生配置来选择LuckyMoneyNewReceiveUI或LuckyMoneyNotHookReceiveUI。此前模块固定启动后者，且仅传红包地址、会话与消息ID，与原生页面选择及完整皮肤参数处理不一致。本版修复这一确定存在的入口差异；不能把静态接口检查表述为已完成报告用户的实际到账验收。

## 原生可见领取入口

收到新红包时保留完整原消息，沿用原账号、名单、秒数延时与去重流程。延时结束后使用微信原生解析器解析原消息，核对红包地址、消息类型、场景和会话，再调用当前注册的钱包插件领取入口。完整皮肤、动态封面等字段由原生模型与原生入口处理，不自行重建，不固定降级到旧页面。

优先使用当前有效且获得焦点的微信Activity，缺少前台页面时使用原生Application路由。微信路由自行处理启动标志和页面容器。v248的启动上下文初始化、恢复及失败撤销界面所有权修复保留。

免费版始终显示原生领取页，再点击可见、可用且获得焦点的拆包按钮，不直接提交静默拆包请求，也不自动回复。高级版/VIP的静默领取接口及权限不变；其前台模式使用本次原生入口。实名、验证及其他原生手动处理要求仍由微信界面处理。

原消息缺失、解析失败、身份不匹配或原生入口不兼容时记录失败，不通过拼接不完整红包或另开旧页面重复提交。页面进入、提前关闭、按钮等待超时及实际领取结果分别记录；超时诊断包含按钮是否显示、是否可用及窗口焦点，不记录红包地址、聊天正文、联系人或金额。声音、跳转及请求提交不视为到账。

## 验证与边界

1464项行为和原微信APK接口检查通过，包含20项上下文与入口委托检查、22项完整消息/皮肤模型与钱包调用检查、37项原生入口/页面选择/应用路由检查，以及新增的延时数据传递和点击超时回归。最终加载器通过168项DEX兼容检查、81项枚举反射检查；真实签名内核升级/前向回退6项，正式和回退APK清单协议8项通过。

测试机保留已有高级版激活和功能设置，安装最终2.09/v250后核对真实字节、内核启动上下文和新旧领取页钩子。手机此前锁屏，具体本次手机验证范围见validation.json；没有为本次测试收取真实红包、转账或向联系人发消息，未实际验收免费版到账。用户报告、手机数据库与现场日志不随源码分发。

## 使用与保留功能

已装2.05或2.07的设备可检查内核更新至v250并重启微信；建议覆盖安装2.09，使内嵌免费内核也包含修复。更新不会重新领取历史红包，请用新收到的红包复测。当前接口基线为微信8.0.80（3220）。此前朋友圈菜单及去广告、转发、转账、原图下载、媒体防撤回和平板权限保持原规则。

Python3/JDK17，依次执行build/build_kernels.py、build/build_loader.py、build/repack_apk.py。独立构建需调整本机工具及历史输入路径，并提供android.jar、xposed-api-82.jar、d8.jar、jadx-all.jar、微信基线APK及自有签名材料。许可证见licenses/。源码不包含私钥、密码、真实激活、用户日志、手机数据库或截图。

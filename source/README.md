# WXEntry 1.91 / 动态内核 v230

本次修复撤回括号备注、右上角“+”模块入口，以及 APK 1.89 在部分框架下钩子全部失效的问题。免费、高级、VIP 三个内核均为 v230。需要覆盖安装模块 APK 1.91，检查动态内核至 v230，再重启微信；单独更新动态内核不能修复旧 APK 内的兼容库。

## 修正和原因

1. APK 兼容库：上传日志的 `NoSuchMethodException ...values []` 来自压缩优化删除枚举反射方法，导致动态 DEX 的框架 API 名称转换失败。后续标准 Xposed API 无法解析，消息钩子为 0；一键已读的 `db0 unavailable` 是数据库钩子未初始化的后续结果。修正最终压缩库的枚举保留规则，枚举类型仍重命名以隔离依赖。用隔离类加载器执行实际压缩后的库，检查生成 DEX 的所有枚举反射接口。签名下载及缓存原件保持不变。
2. 撤回备注：用户自检表明 v228 已拦截并记录撤回，但显示计数为 0。修正 `clickArea` 为空就退出的路径；在同一消息行寻找正文，展示对象的时间与原始记录不同时，依据账号、会话、本地 ID 路由，再读取原始数据库记录严格验证身份。补上微信后续格式化覆盖备注时的刷新，合并刷新请求，清理复用行的旧备注。文本原消息后附“（已撤回）”；媒体使用同一消息内容区域旁的备注。仅影响显示，不写入或新建消息行，不修改消息正文、ID 或收信流程。
3. “+”入口：旧实现用永久“已注入”标记判断弹窗，微信复用、清空或重建内容后可能不再挂载入口。现在检查实时视图中的入口行，显示时延迟重试，允许清空后重新挂载；保留原生项目及顺序，挂载失败恢复原布局。仍只识别首页“+”菜单，不向聊天长按菜单添加入口。

## 验证与限制

912 项内核行为和微信 APK 静态接口检查通过，其中撤回显示 56 项、弹窗重用与恢复 20 项。最终压缩库执行 168 项 DEX 排序、查找、方法体、校验和及原件不变检查；最终 DEX 的 81 项枚举反射接口检查通过。真实加载器使用合成授权完成 6 项签名升级/前向回退检查。APK 1.91 和预留回退 APK 1.92 使用原证书，v1/v2/v3 签名及对齐验证通过。

已核验线上安装包、更新清单及三个内核通道。未连接手机进行本次真机验收，也没有向真实联系人发送消息或触发真实收款。用户报告的 Android 17 / KernelSU / Zygisk Next / LSPosed 完整组合尚未在真实设备上验证，不能仅凭桌面构建测试宣称该环境已经验收。

## 使用与复测

覆盖安装 `wxentry-1.91-recovery.apk` → 检查内核更新至 v230 → 重启微信。首页应显示模块 1.91 / 实际内核 v230；若框架仍注入旧模块，重启手机再检查。适配微信 8.0.80（3220）构建 5032，其他微信版本的原生接口适配限制仍适用。

复测首页“+”入口（连续开关及切换页面后再打开）、撤回后原消息的括号备注、撤回后的下一条消息，以及一键已读。新日志不应再出现旧版 `values []` / 标准 Xposed API 缺失 / 消息钩子全部为 0 的组合。如仍异常，在本版重启后上报自检并提供上报时间；自检增加备注匹配、原始记录核验、目标区域和格式化刷新计数，不额外记录消息正文。

## 源码与构建

这是线上 1.91 / v230 的对应源码，按用户要求，每次产品发布后同步提供。签名私钥、密码、真实激活记录、用户自检日志不包含在源码包内。

Python 3 / JDK 17；现有依赖 android.jar、xposed-api-82.jar、d8.jar、jadx-all.jar。按 `build/build_kernels.py`、`build/build_loader.py`、`build/repack_apk.py` 顺序构建。前两步生成内核和实际优化后的加载器；最后一步需原 APK 基线与原证书材料，路径在脚本中可查看及配置。签名密钥和证书材料由维护者在源码包外提供，不随公开仓库发布。该包保留现有构建脚本结构，不包含 Android Studio/Gradle 工程转换。

加载器使用最小化的 dexlib2 / Guava，许可在 `licenses/` 及 APK `assets/third-party/`。构建依赖源 JAR 哈希见 `validation.json`。授权后台、本次未修改的红包/转账策略和免费/高级/VIP 权限保持原行为。旧专业版由既有后台规则兼容到高级版。

# WXEntry release preference

After each completed product publication, prepare a source ZIP matching the exact published release and include its download link in the final response. The user will sync that source to their GitHub and LSPosed repositories. Keep signing keys, passwords, and real activation records out of the source package.

Tablet mode and native tablet QR login are available only to the advanced (plus) and VIP kernels. Enforce this in both kernel menus and the login-before-account loader using the current activation's verified signed kernel grant. Free and unactivated users must not regain access through an old saved switch or a direct QR entry.

Received-video/file prefetch and the independent automatic original-photo downloader are available in free, advanced and VIP editions. Unrecalled module media copies expire after 180 seconds; recalled copies are retained. Original-photo downloading has its own account-owned personal/group black/white lists, sorted by recent chat, and runs independently of the anti-recall switch. Keep these lists separate from red packet and transfer lists.

One-click Moments forwarding belongs in each post's long-press menu and is available only to advanced (plus) and VIP users. Prepare the target content in a fresh native composer; the user must press Publish. Never call publish/repost/retry APIs or simulate the Publish button. Preserve the text and full media order, recheck account and verified entitlement before opening, and fail visibly if media cannot be prepared. Support new style54 image grids and native Finder cards. Immediately clear cancelled/failed task copies; handed-off copies expire after 24 hours, crash remnants after three minutes, and total module forwarding cache is capped at 512 MiB. Never delete official WeChat cache files as module cleanup.

The user revised the free red packet rule: free users may automatically bring up a visible native receive page and click Open, supporting both native receive pages and the existing account-owned lists and seconds delay. Free users must never use silent API receipt or automatic replies. Advanced/VIP silent reception remains in the background even for ordinary skin red packets.

Native transfer cards can omit total_fee and fee_type. Resolve and validate the amount/currency from the owned native query before confirmation, freeze that amount across the final verification query, and still enforce recipient/payer, authorization, list, delay and manual-guidance checks. Do not turn on a different account's receipt switch during debugging.

The user revised empty whitelist semantics for red packets, transfers and original-photo downloads: a disabled personal/group category processes nobody; an enabled category with an empty whitelist processes everybody, a populated whitelist processes only selected peers, and a blacklist skips selected peers. White/black mode remains mutually exclusive. Keep all three features' settings and accounts isolated.

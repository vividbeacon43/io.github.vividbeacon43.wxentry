# WXEntry release preference

After each completed product publication, prepare a source ZIP matching the exact published release and include its download link in the final response. The user will sync that source to their GitHub and LSPosed repositories. Keep signing keys, passwords, and real activation records out of the source package.

Tablet mode and native tablet QR login are available only to the advanced (plus) and VIP kernels. Enforce this in both kernel menus and the login-before-account loader using the current activation's verified signed kernel grant. Free and unactivated users must not regain access through an old saved switch or a direct QR entry.

Received-video/file prefetch and the independent automatic original-photo downloader are available in free, advanced and VIP editions. Unrecalled module media copies expire after 180 seconds; recalled copies are retained. Original-photo downloading has its own account-owned personal/group black/white lists, sorted by recent chat, and runs independently of the anti-recall switch. Keep these lists separate from red packet and transfer lists.

One-click Moments forwarding belongs in each post's long-press menu and is available only to advanced (plus) and VIP users. Prepare the target content in a fresh native composer; the user must press Publish. Never call publish/repost/retry APIs or simulate the Publish button. Preserve the text and full media order, recheck account and verified entitlement before opening, and fail visibly if media cannot be prepared. Support new style54 image grids and native Finder cards. Immediately clear cancelled/failed task copies; handed-off copies expire after 24 hours, crash remnants after three minutes, and total module forwarding cache is capped at 512 MiB. Never delete official WeChat cache files as module cleanup.

The user revised the free red packet rule: free users may automatically bring up a visible native receive page and click Open, supporting both native receive pages and the existing account-owned lists and seconds delay. Free users must never use silent API receipt or automatic replies. Advanced/VIP silent reception remains in the background even for ordinary skin red packets.

Native transfer cards can omit total_fee and fee_type. Resolve and validate the amount/currency from the owned native query before confirmation, freeze that amount across the final verification query, and still enforce recipient/payer, authorization, list, delay and manual-guidance checks. Do not turn on a different account's receipt switch during debugging.

The user revised empty whitelist semantics for red packets, transfers and original-photo downloads: a disabled personal/group category processes nobody; an enabled category with an empty whitelist processes everybody, a populated whitelist processes only selected peers, and a blacklist skips selected peers. White/black mode remains mutually exclusive. Keep all three features' settings and accounts isolated.

The Moments menu contains independent account-owned switches for one-click forwarding and Moments ad filtering. Both are available only to advanced (plus) and VIP with verified current entitlement. Keep forwarding enabled by default for existing users; ad filtering defaults off. Filter only native advertising markers in the presentation list, preserve ordinary friends' posts and native storage, and explain that refreshing/re-entering Moments applies the ad switch. Turning forwarding off must hide its long-press entry and cancel unfinished preparation. The user authorized enabling ad filtering on the connected test machine.

Application context must be initialized from the existing boot Activity or current Application before runtime hooks; do not rely on a future LauncherUI.onCreate event after the kernel has loaded. Recover it on Activity resume and lazily before visible red-packet reception. Prefer a live focused WeChat Activity for native UI launch, retain only application context, and clear launch ownership if starting the page fails. Keep free receipt visible and never enable silent receipt or replies for free.

Visible red-packet launches must delegate to the current WeChat native wallet receive entry using its parsed complete original card model and the owned session/message ID. Let the host select NewReceiveUI or NotHookReceiveUI and preserve skin/scene extras; never hard-code the old receive activity or downgrade to a partial reconstructed card. Log page entry, premature closure and click timeout separately from actual receipt success.

Moments simulated likes and comments are private local presentation features, available only to verified advanced (plus) and VIP accounts. Provide separate account-owned default-off switches, friend selection, native avatar/profile navigation, editable comment presets and per-comment editing/deletion. Bind records to the exact account, author and post ID; preserve genuine native interaction views and records. Never submit actual likes/comments, alter SNS databases/protobufs or send notifications. Keep bounded private records separate from existing Moments settings; clear only module-owned views/records and remove temporary test records after validation.

Simulated Moments likes must use the host's native interaction/likes layout, heart and comma-separated friend names with working profile links. Preserve and restore genuine like views when combining presentation text. Do not impose a fixed 100-person cap; select-all covers all available friends, and a user-entered random count chooses distinct friends from that same full pool, replacing the current selection. Search only changes the visible list, and cancelling random selection leaves current choices intact. Keep large local lists incrementally expandable and bounded by private storage size rather than a fixed person count.

Red packet greeting and automatic transfer memo keyword filters are VIP-only, enforced in menus and before automated operations with a verified VIP kernel grant. Each feature/account owns a separate keyword set, literal fuzzy/whole-text exact matching, and mutually exclusive Skip-hit/Only-hit switches; both off disables keyword restrictions. Existing personal/group black/white rules still apply. Recheck after delays and before opening/confirming; unavailable text with an active filter must not trigger automatic receipt. Never match names, amount, raw XML or unrelated messages. Do not apply saved VIP keyword filters on non-VIP kernels. The user requested upgrading the connected test account to VIP and will send real test red packets after the candidate is installed; wait for this requested test before production publication. Keep charging stay-awake enabled at 7 permanently, as explicitly requested.

The donation menu in all editions opens https://www.zidianidc.com/shop/Z2EWXNI6 in an external browser. If no usable browser can launch, copy that same URL to the clipboard and tell the user it was copied. Preserve real receipt test evidence when making an independent donation-only edit; verify receipt source code remains identical and test the changed donation behavior before publication.
